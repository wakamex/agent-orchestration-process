## Upgrading from 0.2.x

Run `aop migrate-results` once after upgrading. Results now record the state directory they ran in, and AOP refuses to load a result without it until the migration adds it. The migration keeps each rewritten record's original beside it and writes nothing with `--dry-run`. [Token usage and pricing](https://github.com/wakamex/agent-orchestration-process/blob/v0.3.0/docs/token-usage.md) describes every conversion.

## Results archive

Every result is now also written, with the same content, to `~/.local/state/aop/results/RUN_ID.json` (under `$XDG_STATE_HOME` when set). Usage and cost therefore survive when the directory holding a run's `.aop` is deleted, as benchmark harnesses do with per-question profiles. Each result's new `state_root` field names the `.aop` directory it was recorded in, so consumers such as clanker-analytics can attribute archived runs to their project. `aop migrate-results` fills the archive from existing runs and removes duplicate and deleted directories from the `state-roots` list, which concurrent runs no longer duplicate.

## Cache writes and resumed Claude costs

- Results now count cache writes separately: `cache_write_input_tokens` and `cache_write_1h_input_tokens` are subsets of `input_tokens` for the harnesses that report them (Claude, Cursor, DeepSeek Harness, Grok and OpenCode). API-equivalent costs price them at the cache-write rates instead of the plain input rate. The migration recovers both fields from each run's `events.jsonl`.
- A resumed Claude Code session reports the whole session's running cost. A resumed run's cost is now its own turn: the parent run's reported total is subtracted. A fresh run whose report includes a second model, such as a subagent's, keeps its reported cost.
