This release restores two harnesses that had stopped working and closes a `--no-web` gap in a third.

- [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (dsh) 0.2.1-rc.2 is supported. dsh 0.2 calls DeepSeek's Anthropic-compatible Messages API and reads its API key from the launch environment, so AOP now passes the key you keep in `~/.dsh/.credentials.yaml` (its `version: 1` layout) as `DEEPSEEK_API_KEY` when none is exported. Before, AOP read that file in an older layout and runs did not receive a key kept only there. AOP also turns off dsh 0.2's default upload of each session's log with every request, and under `--no-web` disables its `web-deepseek-api` plugin.
- Hermes runs work again. Hermes's current installer publishes a launcher that AOP did not recognize, so every Hermes run failed before starting. AOP now asks the launcher for its own command with `hermes --print-runtime-command`, mounts its Python, checkout and tools read-only in isolated profiles, and gives its dependency store a temporary overlay for the lock files Hermes writes at startup. Runs set `HERMES_DISABLE_LAZY_INSTALLS=1`, so a task never installs dependencies, finishes a pending Hermes update, or rewrites Hermes's launchers. Task homes move to `hermes/profiles/aop` in each task's state, and an existing `hermes/home` is moved there.
- Grok `--no-web` runs no longer offer `search_tool` and `use_tool`, which Grok 1.0.60 added to find and call connected MCP servers' tools.

New opt-in native tests check the installed dsh and Grok without quota: `AOP_TEST_DSH_BIN=/path/to/dsh` runs dsh against a local Messages API server, and `AOP_TEST_GROK_BIN=/path/to/grok` checks the tools a `--no-web` Grok run offers.
