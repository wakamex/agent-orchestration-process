AOP 0.6.1 ends Cursor runs that finished their work but never exited.

- When background shell tasks finish late in a turn, Cursor Agent 2026.10 can answer them in a follow-up turn that its `stream-json` output never shows, and then keep running without reporting a result, so a run idled until its `--timeout`, hours after the work was done. AOP now watches Cursor's own transcript of the chat. Once it records a new turn end and Cursor has stayed running and silent for 60 seconds, AOP stops Cursor. The run fails with an error saying so, keeps the answer from the transcript and the chat ID for `aop resume`, and reports accounting `unavailable`, since Cursor reports usage only in its result. A turn that is still working, such as a long silent build, records no turn end, so only `--timeout` limits it ([`296c075`](https://github.com/wakamex/agent-orchestration-process/commit/296c0756f241fac5d0a2ed02a2d80fa76194dace)).
- Cursor runs that end without a result now report accounting `unavailable` instead of zero usage marked complete ([`296c075`](https://github.com/wakamex/agent-orchestration-process/commit/296c0756f241fac5d0a2ed02a2d80fa76194dace)).
