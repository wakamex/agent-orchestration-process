AOP 0.6.3 adds an admission command that every run must pass, keeps a run's Claude sign-in in step with yours, and documents launching AOP from a checkout.

- An admission command can decide whether a run may start, for example by checking a subscription's remaining quota. Every `aop run`, `aop resume`, batch task, and integration resume asks it, taking it from `--admit-command`, then `AOP_ADMIT_COMMAND`, then `admit_command` in `~/.config/aop/config.toml`. It receives the run, including its harness, model, profile, credential home, and the inference provider it spends, as JSON on stdin; exit 0 admits the run, and anything else, including a command that cannot run or takes over 60 seconds, refuses it before any state exists, with exit status 2 and one JSON line on stdout. Each run's request, result, and archived result record the decision, or an explicit opt-out. AOP itself holds no quota logic. See [Running unattended](https://github.com/wakamex/agent-orchestration-process/blob/main/docs/unattended.md#admission-before-a-run-starts) ([`3bed952`](https://github.com/wakamex/agent-orchestration-process/commit/3bed9525bfce9b8629eda07d3911d3e44d75778a)) ([`4f5582c`](https://github.com/wakamex/agent-orchestration-process/commit/4f5582c1b8221c298b311685be93ede86f4fd665)).
- A Claude sign-in refreshes with a rotating refresh token, so a refresh in one copy of it invalidates the others. A run's private sign-in now stays in step with yours: before the run, every few seconds during it, and after it, a refresh on either side is copied to the other. Long Claude runs no longer fail with "OAuth session expired" when the sign-in refreshes mid-run, a run's refresh no longer signs your own sessions out, and a resumed task picks up a sign-in you renewed since ([`beae3c9`](https://github.com/wakamex/agent-orchestration-process/commit/beae3c9d885b41a2dd611795493dc011ec707940)) ([`f9f07a8`](https://github.com/wakamex/agent-orchestration-process/commit/f9f07a8c9dd59c77a09dc00369e1ae0015498e3c)).
- [CONTRIBUTING](https://github.com/wakamex/agent-orchestration-process/blob/main/CONTRIBUTING.md) explains how other projects can run AOP from a checkout without a lockfile check that breaks when a uv command records user-level options in `uv.lock` ([`e1a04b5`](https://github.com/wakamex/agent-orchestration-process/commit/e1a04b574d4421133672e0f2d7efdc4689e7d026)).
