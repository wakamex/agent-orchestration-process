AOP 0.7.0 keeps long Claude and Devin runs alive, keeps the artifacts a run did write, records which directory each run worked in, and stops seeding gigabytes of Claude runtime data into every run.

A correction to the 0.6.3 notes: admission is optional. With no admission command configured, runs start without a check, as before; once one is set in `~/.config/aop/config.toml` or `AOP_ADMIT_COMMAND`, no run needs an extra argument ([`0695175`](https://github.com/wakamex/agent-orchestration-process/commit/0695175aff7725c86a19bd214c69b7a01496c1a0)).

## Claude sign-in

- A Claude sign-in refreshes with a rotating refresh token, so a refresh in one copy revokes every other copy at once. Host runs now sign in with your own credentials file through `CLAUDE_SECURESTORAGE_CONFIG_DIR`, sharing it and Claude's refresh lock with your own sessions, and AOP keeps no private copy of the sign-in for them ([`6ad3852`](https://github.com/wakamex/agent-orchestration-process/commit/6ad385254989f1ef26a7029fb221907d4a549993)).
- Sandboxed runs cannot reach that file, so their private copy is now kept in step with yours within about 100 ms instead of five seconds, before Claude gives up on a request rejected after a refresh ([`0c3c25c`](https://github.com/wakamex/agent-orchestration-process/commit/0c3c25cea500e4035d474e8081e5f82d5ca37832)).

## Devin usage limits

- A Devin run with a `--timeout` now waits out its free-model rate limit as many times as the deadline allows; the cap of ten waits applies only to runs without a deadline. A run whose usage Devin never reported now has accounting `unavailable` instead of zero tokens marked complete ([`56070cf`](https://github.com/wakamex/agent-orchestration-process/commit/56070cfe7a29bc587d6fa4a7b2aa2dfcd43113ed)).
- Limit messages that give the reset with a date, such as "(at Nov 6 00:01 UTC)", or only as "reset in N minutes", are now recognized as limits ([`1a09b26`](https://github.com/wakamex/agent-orchestration-process/commit/1a09b26924e6a9b4341a1358d3c3a92853c70340)).

## Artifacts

- One missing or invalid artifact still fails the run, but no longer discards the artifacts that were written: each declaration is checked on its own, and every artifact written correctly is archived ([`03351b2`](https://github.com/wakamex/agent-orchestration-process/commit/03351b254932ecf9f3a3d357b08742317b69361f)).
- `--artifact 'icon.svg|icon.png'` declares alternatives: it is met when at least one is written, and every one written is archived ([`03351b2`](https://github.com/wakamex/agent-orchestration-process/commit/03351b254932ecf9f3a3d357b08742317b69361f)).

## Run records and disk use

- Every result, including the results archive, has `project_dir`: the `--workdir` directory, the repository that owns the task worktree, or null for sealed runs. `aop migrate-results` fills it in on older `--workdir` results from their requests ([`0737b97`](https://github.com/wakamex/agent-orchestration-process/commit/0737b97a7425936e088a9d73dcba06fd98d799ee)) ([`0dc17eb`](https://github.com/wakamex/agent-orchestration-process/commit/0dc17eb2556702f342e77efcd884a17dcee072c4)).
- A Claude run's private home no longer copies runtime folders such as `jobs`, `file-history`, `paste-cache` and caches, which could make each run's state gigabytes. `aop cleanup RUN_ID` and `aop cleanup --all` now also remove a `--workdir` run's private state, leaving its directory alone, and `--all` also cleans the current directory's `.aop` when it differs from the repository's ([`fc7da49`](https://github.com/wakamex/agent-orchestration-process/commit/fc7da49ceccf320b433dd3e80fd92a68eab28a30)) ([`9797ecf`](https://github.com/wakamex/agent-orchestration-process/commit/9797ecfbbbe2603acc6cff457de6f8e88932c4fd)).
- `aop models` lists `cache_write_1h_per_million_usd`, the rate for writes to a longer-lived cache such as Anthropic's one-hour cache, which Claude Code mostly writes to ([`677b733`](https://github.com/wakamex/agent-orchestration-process/commit/677b733f86d247a9c8d4ec15d2bff2773cdac8b4)).
